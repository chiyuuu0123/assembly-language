# DEBUG 单步跟踪：n=4

[TRACE.ASM](TRACE.ASM) 是无键盘干扰的最小调试驱动，设置 BX=4 后，调用与交互主程序相同的 [FIB 过程](FIBCORE.INC)。[TRACE.LOG](TRACE.LOG) 为真实 FreeDOS DEBUG 输出；以下数据从连续两条寄存器快照提取。

## 如何观察

在 DOSBox 的作业目录输入 `BUILD.BAT`，然后输入 `DEBUG TRACE.EXE`。用 `R` 看初始寄存器，反复用 `T` 每次执行一条指令。快照下方列的是下一条待执行指令；当它为 CALL、RET、PUSH 或 POP 时，对比本次与下一次快照中的 SP。用 `Q` 退出调试器。

要重现完整日志，执行 `DEBUG TRACE.EXE < STEPS.TXT > TRACE.LOG`。脚本的 `T 90` 让 DEBUG 连续执行单步（计数为十六进制），目标程序在计数用完前已正常退出；DEBUG 仍逐条记录寄存器。段地址随装载位置变化，表中只列本次构建的 IP 偏移。

## 本次运行的全部栈变化

| 执行前 IP | 指令 | BX 前 → 后 | SP 前 → 后 | 执行后 IP |
| --- | --- | --- | --- | --- |
| `000Ah` | `CALL 0012` | 4 → 4 | `0800h` → `07FEh` | `0012h` |
| `001Fh` | `PUSH BX` | 4 → 4 | `07FEh` → `07FCh` | `0020h` |
| `0021h` | `CALL 0012` | 3 → 3 | `07FCh` → `07FAh` | `0012h` |
| `001Fh` | `PUSH BX` | 3 → 3 | `07FAh` → `07F8h` | `0020h` |
| `0021h` | `CALL 0012` | 2 → 2 | `07F8h` → `07F6h` | `0012h` |
| `001Fh` | `PUSH BX` | 2 → 2 | `07F6h` → `07F4h` | `0020h` |
| `0021h` | `CALL 0012` | 1 → 1 | `07F4h` → `07F2h` | `0012h` |
| `0073h` | `RET` | 1 → 1 | `07F2h` → `07F4h` | `0024h` |
| `0025h` | `CALL 0012` | 0 → 0 | `07F4h` → `07F2h` | `0012h` |
| `0073h` | `RET` | 0 → 0 | `07F2h` → `07F4h` | `0028h` |
| `0028h` | `POP BX` | 0 → 2 | `07F4h` → `07F6h` | `0029h` |
| `0073h` | `RET` | 2 → 2 | `07F6h` → `07F8h` | `0024h` |
| `0025h` | `CALL 0012` | 1 → 1 | `07F8h` → `07F6h` | `0012h` |
| `0073h` | `RET` | 1 → 1 | `07F6h` → `07F8h` | `0028h` |
| `0028h` | `POP BX` | 1 → 3 | `07F8h` → `07FAh` | `0029h` |
| `0073h` | `RET` | 3 → 3 | `07FAh` → `07FCh` | `0024h` |
| `0025h` | `CALL 0012` | 2 → 2 | `07FCh` → `07FAh` | `0012h` |
| `0073h` | `RET` | 2 → 2 | `07FAh` → `07FCh` | `0028h` |
| `0028h` | `POP BX` | 2 → 4 | `07FCh` → `07FEh` | `0029h` |
| `0073h` | `RET` | 4 → 4 | `07FEh` → `0800h` | `000Dh` |

- 初始 SP=`0800h`。首次 `CALL` 将 SP 降至 `07FEh`，最后一次 `RET` 恢复到 `0800h` 并返回主程序 `000Dh`。
- 最深处为 `07F2h`，比初始少 14 字节：4 个返回地址和 3 份保存的 BX，各占 2 字节。
- 首次递归沿 4→3→2→1 下探；F(1)、F(0) 为初始缓存命中。回到 n=4 后再次调用 F(2) 时，F(2) 已算好，所以只有 CALL/RET，没有新的 PUSH/POP。
- 7 次 CALL、7 次 RET、3 次 PUSH 和 3 次 POP 都满足相应的 2 字节增减，检查脚本会从原始日志重新验证。
